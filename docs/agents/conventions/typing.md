# Строгая типизация

Доменные типы и пропсы компонентов объявляют свои настоящие поля. `unknown` в любой позиции (`unknown`, `unknown[]`, `Record<string, unknown>`,
поле типа `unknown`) означает, что форму не посмотрели, — найти её и описать, а не расширять тип. `unknown` допустим только в обобщённой утилите,
которая по замыслу принимает любую форму; `any` и необъяснённые `as` недопустимы нигде.

**Где смотреть форму.** Формы GREEN-API — из документации API (https://green-api.com/telegram/docs/api/) и проверенных фактов
в `plans/messenger-v1/brainstorm.md`, никогда не выводятся из места вызова. Собственные сущности проекта — `src/types/<domain>.types.ts`.
Ответы и уведомления GREEN-API — внешние данные: на границе (в сервисе, в poller'е) они разбираются zod-схемой, дальше идут только типы проекта.

**Ограниченный набор строковых значений — строковый `enum`**, а не union литералов (`"a" | "b"`) и не сравнение с голой строкой
(`x === "a"`): виды ошибок, причины, дискриминанты вариантов (`kind`), режимы и виды экрана в `useState`, значения полей GREEN-API, с которыми
сравнивает код. Члены — `UPPER_SNAKE_CASE`, значения — как в данных. Значения полей API собираются в `enum` из тех, что код использует; zod-схема при этом
не сужается там, где API может прислать значение вне набора (поле остаётся `z.string()`, код сравнивает с членами `enum`). `enum` значений полей
GREEN-API объявляется в `*.schema.ts` своего домена. **Исключение — пропсы компонентов:** там union литералов допустим, чтобы потребителю не
импортировать `enum` ради одного пропа.

Если ключи словаря ограничены enum, словарь типизируется как `Record<EEnumName, ValueType>` (или `Partial<Record<EEnumName, ValueType>>`,
если есть не все члены). При наличии enum по умолчанию — `Record` по enum, а не `Record<string, X>`. Так же — для любого нового словаря-справочника.

# Роуты и страницы

Роутинг — TanStack Router в **code-based** режиме: дерево роутов написано явно, без кодогенерации и `routeTree.gen.ts`.

- `src/routes/` — только дерево: константы путей (никаких строковых литералов путей в компонентах), роуты, сборка роутера. Компонентов здесь нет —
  роуты импортируют экраны из `src/pages/` и каркасы из `src/layouts/`.
- **Фабрики роутов, принимающие родителя параметром, обобщены по нему** (`<TParent extends AnyRoute>(parent: TParent)`), а не принимают `AnyRoute`:
  с `AnyRoute` пути и id детей собираются из `any`, и у `Link` / `navigate` / `redirect` / `useSearch` молча пропадает проверка путей, `search` и `params`.
- **Guard авторизации — `beforeLoad` защищённого layout-роута**, а не компонент-обёртка: срабатывает до рендера, защищённый экран не мелькает.
- `src/pages/<Name>Page/` — сам экран по конвенциям компонентов; части страницы — в её `_internal/`. Экран индексного роута — тоже страница.
- `src/layouts/<Name>Layout/` — каркас layout-роута (общая обвязка нескольких экранов: колонки, панели, фоновые процессы каркаса);
  устроен как страница — части в его `_internal/`, лестница `structure.md` та же.

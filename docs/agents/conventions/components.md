# Компоненты

## Состояния загрузки

Секция, которая загружает данные, показывает явное состояние загрузки — скелетон или собственный плейсхолдер проекта — пока идёт запрос.
**Нельзя** сначала рисовать `-` или пустые места и подменять их значениями по приходе: «прочерки, а потом скачок» — заметный дефект.
`-` — для значения, которого действительно нет _после_ загрузки, а не для «ещё не загрузилось».

## Размер компонента

**Компоненты тонкие.** Тело рендера — JSX и тривиальная склейка. Загрузка данных, вычисления, преобразования и нетривиальная логика —
в соседнем хуке (`_use<Name>.ts`) или `_helpers.ts`, никогда не в теле рендера. `.tsx`, в котором заметная не-JSX логика или больше ~150–200 строк, —
сигнал: вынести и разместить по лестнице из `structure.md`. Новый компонент больше 200 строк требует обоснования.

## Составные компоненты — только для компонуемых оболочек

Когда несколько экранов (или вариантов одного экрана) делят раскладку, но различаются **тем, что в неё вставлено**, общая часть оформляется
**составным компонентом**: корень плюс именованные подкомпоненты как статические свойства, которые потребитель расставляет своим JSX.

**Состояние остаётся у потребителя.** Подкомпоненты — глупая разметка; корень не прячет общее состояние во внутренний контекст.
Логика, которую потребители иначе дублировали бы, — в хуке рядом с составным компонентом.

**Это исключение, а не норма.** Применять, только когда набор слотов действительно **различается между потребителями**. **Не** делать компонент составным, если:

- у него одно место вызова или все места рендерят одну и ту же структуру — оставить одним компонентом;
- различие выражается пропом-значением (`variant`, `size`, boolean, enum) — использовать проп;
- различие — **единообразное внутреннее решение**, а не выбор потребителя. Канонический пример — состояния загрузки и пустоты: если каждый потребитель
  написал бы одну и ту же проверку `isPending` / `isEmpty`, она живёт **внутри** корня и управляется пропсами, а не выставляется подкомпонентами
  `.Preloader` / `.Empty` для сборки каждым потребителем.

**Небольшой `ReactNode` в пропе — нормально и часто лучше.** Один элемент через именованный проп — вариант по умолчанию для единственной точки вставки;
составной подкомпонент — когда потребителю нужно **расставить несколько** частей внутри оболочки.

**Именование.** Корень составного компонента не должен совпадать по имени с сущностью другой природы — в частности, layout-роуты в `src/routes/`
(провайдеры контекста и `<Outlet />`) — отдельная история от презентационных оболочек; одинаковых имён у них быть не должно.

# i18n

Словари — `public/dictionaries/`, сейчас один `ru.json`. Интерфейс только на русском; инфраструктура есть, чтобы тексты с самого начала жили
в одном месте, а не выковыривались из JSX потом. Интерфейс словаря — `src/types/i18n.types.ts`, хук выборки — `useI18nSelector`.

## Все тексты — через словарь

Весь видимый пользователю текст (подписи, плейсхолдеры, подсказки, ошибки, пустые состояния) идёт через i18n, никогда не хардкодится в JSX.
Новый ключ добавляется **во все** словари папки одновременно (перечислять папку, а не держать список в голове), значение — на языке файла.
Ключ только в части словарей ломает переключение языка и считается дефектом.

## Ключи — идентификаторы, а не данные

Ключ соответствует `^[A-Za-z0-9_]+$`: латиница, цифры и `_`. Без кириллицы, пробелов, пунктуации и разделителей вроде `;` или `/`.
Обычные ключи — `camelCase`; ключи для значений enum — `UPPER_SNAKE_CASE` и совпадают с членом enum.

Правило защищает от сырого внешнего значения в роли ключа: такой ключ становится частью публичного типа `I18n`, недоступен через точку
и молча ломается, как только источник переформулирует значение. Если значение не годится в ключ — значит, **данным** нужен код.

## Типизация словарей значений

Если у ограниченного набора значений есть enum, словарь — `Record<EEnumName, string>`. Если enum нет — обычный объектный тип с явными ключами.
Никогда не `Record<"literal" | "another", string>`: union строковых литералов выглядит проверенным типом, но фиксирует точное написание источника,
и переименованное значение падает в рантайме, а не при компиляции. Это то же правило, что для словарей в `typing.md`.

## `useI18nSelector` выбирает узкий срез

Селектор возвращает конкретную ветку (или объект из нескольких веток), которая нужна компоненту, — никогда не корень `l`. Весь словарь
подписывает компонент на любое изменение переводов и скрывает, от какой части он на самом деле зависит. Взять `l` и сузить уже в теле компонента —
та же ошибка, записанная иначе.

**Один `l` на компонент, аргумент селектора — всегда `({ l })`.** Результат селектора — в одну `const l`; чтение — `l.sendButton`,
никогда `composer.sendButton`. Собирается разворотом основной ветки компонента и дополнительными ветками под именованными ключами:

```ts
const l = useI18nSelector(({ l }) => ({
  ...l.chatPage.composer,
  errors: l.common.errors,
}));
```

Компонент без основной ветки (общий фрагмент) обходится без разворота, только именованные ключи. Дефекты: переименование аргумента
(`({ l: localization }) => …`) и деструктуризация результата в несколько имён (`const { l, errors } = …`) — обе ломают соглашение,
по которому чтения i18n ищутся поиском: `l` — это срез словаря, везде.

## `src/types/i18n.types.ts` экспортирует ровно одно — интерфейс `I18n`

Этот файл — форма словарей и больше ничего. Вспомогательные типы, используемые _внутри_ него (union ключей, алиасы enum), объявляются в доменном
файле, которому принадлежит понятие (`src/types/<domain>.types.ts`), и импортируются сюда. Иначе зависимость переворачивается: потребители
начинают импортировать словарь домена из файла переводов. Правила размещения типов (`structure.md`) действуют без изменений.

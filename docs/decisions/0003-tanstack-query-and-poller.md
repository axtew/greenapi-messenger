# 0003. TanStack Query как хранилище + poller вне React

- Статус: принято
- Дата: 2026-10-03

## Контекст и проблема

Данные приходят двумя путями: запросами (история, отправка, профиль собеседника) и бесконечным циклом получения уведомлений.
Нужно одно место, где лежат сообщения, и понятная граница между циклом и UI.

## Рассмотренные варианты

1. **TanStack Query + poller — отдельный TS-модуль**, пишущий в кэш через `setQueryData`.
2. Свой store (reducer + `useSyncExternalStore`) без TanStack Query.
3. Zustand.
4. Самописный `HTTPService` автора из другого проекта + Context.

## Решение

**Вариант 1.** Загрузка, ошибки, повторы и optimistic update — из коробки; хранилище сообщений одно — кэш запросов;
цикл получения не зависит от жизненного цикла компонентов. Варианты 2 и 4 требуют писать то же руками;
3 — лишняя зависимость. `HTTPService` рассчитан на обновление токена и повторы, которых у GREEN-API нет.

## Последствия

- В один ключ кэша пишут и история, и poller → обязательна дедупликация по `idMessage`.
- Уведомления разбираются zod-схемой на границе: это внешние нетипизированные данные.

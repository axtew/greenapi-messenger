## Issues

### Code issues

#### Комментарии
- [code] `e2e/messenger.spec.ts:6` — комментарий утверждает, что поле ввода «занимает всю ширину колонки». В коде это не так: у `SForm` (`src/pages/ChatPage/_internal/Composer/_styles.ts:13-22`) отступ слева 20px, справа 6px, плюс кнопка 44px и `gap: 8px`. Поэтому середина `textarea` смещена влево от середины колонки примерно на 19px. На короткие пузыри сценария это не влияет, но комментарий описывает свойство, которого у кода нет (`code-style.md` → «Комментарий, приписывающий коду свойство, которого нет»). Есть два варианта исправления. Можно мерить середину по `chatScreen` (`getByRole("main")`): это и есть колонка, а лента в ней отцентрирована (`max-width: 880px`). Тогда `getChatColumnCenterX` станет точным, и комментарий будет верным. Либо можно честно переписать комментарий: «примерная середина колонки — по полю ввода; смещение на ширину кнопки отправки для коротких пузырей не важно».

#### Дисциплина экспорта
- [code] `e2e/greenApiStub.ts:43` — у `export interface IGreenApiStub` нет импортёра: `messenger.spec.ts` получает объект из `installGreenApiStub` и тип не называет. Обоснование из отчёта iter-1 («тип возвращаемого значения экспортируемой функции, контракт модуля») ни под одно исключение `structure.md` → «Дисциплина экспорта» не подходит. Там прямо сказано, что неэкспортированный интерфейс доступен структурно через экспортированную сигнатуру, а экспорт нужен, только когда потребитель должен назвать тип. Нужно убрать `export`.

#### TypeScript
- [code] `e2e/greenApiStub.ts:38-41, 55-60` — `INotification.body: Record<string, unknown>` описывает форму, которая известна и которую стаб сам целиком строит в `pushIncoming` (`incomingMessageReceived`, `brainstorm.md` → «Формы уведомлений»). `readBody` приводит тело через `as Record<string, unknown>` без пояснения. Из-за этого дальше по коду повсюду стоят `String(body.chatId)`, `Number(body.count)`, `String(body.phoneNumber)`, а в строке 142 `chatId: body.chatId` пробрасывает `unknown` в ответ. Это противоречит `typing.md`: «`Record<string, unknown>` означает, что форму не посмотрели», «необъяснённые `as` недопустимы нигде». Предлагаемое исправление: описать тело уведомления интерфейсом по `brainstorm.md`, а для тела запроса приложения завести интерфейс с полями, которые шлют сервисы (`chatId`, `count`, `phoneNumber`, `message` — все необязательные). Тогда приведение в `readBody` станет одним явным `as` с однострочным пояснением: «тело шлёт наше приложение — форма известна по сервисам». Другой вариант — разбирать тело zod-схемой (zod уже в зависимостях).

## Summary
Проверена Phase 3 «Вход и маршруты» вместе с поправками «Phases 2, 3, 6, 7, 9» (п. Phase 3) и «Phase 3 — added 2026-10-05» по рабочему дереву относительно `e492529`. #### Comments
- [code] `src/app/_queryClient.ts:24-27` — первая строка JSDoc `isRetriable` («Стоит ли повторять запрос: да — для сбоя сети и ответов 5xx») расходится с кодом: функция возвращает `true` для **любой** ошибки, которая не `GreenApiError`, то есть и для `TypeError` из бага в `queryFn`, и для чего угодно ещё. Предикат соответствует плану («без повторов для `GreenApiError` со статусом < 500»), поэтому править нужно комментарий: первая строка должна описывать фактическое правило (не повторяется только ответ GREEN-API со статусом ниже 500, всё остальное повторяется).
- [code] `src/app/_queryClient.ts:33-37` — JSDoc `queryClient` утверждает: «Ответ 401 в любом запросе или мутации означает, что токен… больше не действует: сессия завершается». Мутации с `meta.skipUnauthorizedRedirect` (вход) это правило обходят (`_queryClient.ts:47`). Исключение описано только у поля `TMutationMeta`, а комментарий уровня модуля его не упоминает. Нужно добавить оговорку («…кроме мутаций, помеченных `skipUnauthorizedRedirect`»).
- [code] `src/hooks/useForm/_useForm.hook.ts:20-21` и `:136-138` — комментарии описывают recipe-book, а не этот код. В JSDoc примеры `resetOn` — «лист (`isOpened`)» и «редактор рецепта (`recipeId`)», которых здесь нет. В `catch` у `onSubmit` сказано, что «сообщение об ошибке уже показывает общий MutationCache», но здесь `MutationCache` только уводит на вход при 401, а ошибку входа показывает форма (`_useLoginForm.ts:79`). По `code-style.md` → «Комментарии» комментарий, приписывающий коду несуществующее свойство, — дефект. Разработчик честно указал это в Known issues. Поправить после решения владельца по plan-issue ниже: «отражать структуру образца, а не его долг».

#### Размещение `EGreenApiMethod`
- [plan] Поправка «Phase 3 — added 2026-10-05» требует типизировать `method` клиента этим enum и оставляет место «по лестнице `structure.md`». Клиент не может импортировать из сервисов (сервисы импортируют клиент), поэтому enum оказался в `src/api/greenApi/_types.ts` (`:17-28`) и экспортируется через barrel клиента. Это расходится с `docs/agents/architecture.md:19`: «Сервисы — единственное место, знающее URL и имена методов GREEN-API». Поправка этот конфликт не называет. Размещение по лестнице корректно: значения передают только сервисы, клиент знает лишь тип. Нужна правка документа, а не кода: в `architecture.md` указать, что набор имён методов — enum слоя клиента, а **передают** их только сервисы. Владелец может решить иначе (например, вынести enum в отдельный модуль `src/api/`), но тогда это нужно записать в план.

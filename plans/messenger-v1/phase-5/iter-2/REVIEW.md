## Issues

### Code issues

#### Корректность синхронизации

- [code] `src/api/queries/chats.queries.ts:26-36`, `:66-72`, `:84-88` — при сбое `getContact` у чата, который **уже есть** в списке
  с `isProfileLoaded: false`, `fetchContact` возвращает запасной профиль `{ name: chatId, phone: null, username: null, avatarUrl: null }`, и `upsertContact`
  применяет его поверх существующей записи: ветка `existing.isProfileLoaded && !isProfileLoaded` (`src/api/cache/chats.cache.ts:78`) защищает только
  загруженный профиль. Это противоречит п. 2.5 плана: «чат остаётся с тем, что есть». Временный профиль с более полезными данными появится
  в следующих фазах:
  - Phase 6, `plan.md:603`: при сбое `getContact` контакт берётся из `checkAccount` — имя `@username` / `+phone`, заполнены `phone` и `username`;
  - Phase 9, `plan.md:789`: имя `chatName || senderName`.

  При следующем входе с исчерпанной квотой `getContactInfo` (на тарифе «Разработчик» их 100 в месяц — это рабочий, а не редкий случай) синхронизация
  заменит такое имя числовым Telegram-id и обнулит `phone` / `username`. В Phase 6 пропадёт и подзаголовок `ChatHeader`.

  Как поправить: запасной профиль создаётся только для чата, которого нет в списке **на момент слияния**. Известный чат при сбое `getContact` остаётся
  без изменений и с прежним `isProfileLoaded: false`. Например, `fetchContact` при сбое возвращает `null`, а внутри `updateChats` для `null` заглушка
  добавляется, только если `chatId` нет в `chats`. Нужен тест в `chats.queries.test.ts`: «сбой профиля у известного чата с временным профилем оставляет
  его имя, `phone` и `username`». Сейчас `:156-163` проверяет только новый чат.

#### Стили

- [code] `src/layouts/MessengerLayout/_internal/Sidebar/_internal/ChatListItem/_styles.ts:30-37` вместе с `_ChatListItem.tsx:27-29` и `:38-42` —
  `overflow` / `text-overflow: ellipsis` / `white-space` заданы на обёртке `SEllipsis`, а шрифт и цвет — на вложенном `H3` / `B1` (`as="span"`).
  По CSS Overflow 3 многоточие рисуется стилем **блочного контейнера**, то есть `SEllipsis`. Этот контейнер наследует от `body`
  `color: palette.text` (`#000`) и вес 400. В результате у серого превью (`B1 textMuted`) «…» получается чёрным, а у имени (`H3 medium`) — тоньше
  самого текста. Это видно на любом длинном превью.

  Как поправить: правила обрезки должны стоять на том же элементе, что задаёт шрифт и цвет. Варианты:
  - стилизованная обёртка над `H3` / `B1` — она оправдана, потому что `text-overflow` пропом не выражается;
  - `SEllipsis` наследует цвет и шрифт от текста — например, `color` выставляется на нём, а внутренний span получает `inherit`.
